# Задание: TS — приложения и мини-ПК «скачал и работает»

Инструкция для следующей сессии Claude. Прочитай целиком, потом README.md.

## Правила
- Продукт называется **TS**. Расшифровку названия нигде не пиши.
- Общайся с пользователем по-русски, просто, как с владельцем бизнеса, а не программистом.
- Репозиторий `github.com/ansa-music/billS`, рабочая ветка — от `main`. Пуш в `main` запускает выкладку сайтов (Cloudflare Pages + Supabase), поэтому сливай только зелёное (`npm test`, `npm run typecheck`, `npm run build`).
- Node 24: `C:\Program Files\nodejs` (в bash: `export PATH="/c/Program Files/nodejs:$PATH"`).
- **Публичные выпуски (GitHub Releases) создавай только после явного «да» пользователя в чате** — это публикация для всех. Секреты, токены, ключи подписи в чат не выводи и в код не клади; если нужен новый секрет — объясни пользователю, куда его вставить в GitHub (Settings → Secrets and variables → Actions).
- Дели работу на субагентов по непересекающимся файлам — пользователь разрешил.

## Что сделать

### 1. Android: APK одной кнопкой
- `.github/workflows/mobile.yml`: по метке `mobile-v*` (и `workflow_dispatch` для пробной сборки без выпуска) — Node 24, JDK 21, Android SDK, `npm ci`, сборка веб-части, `npx cap sync android`, `./gradlew assembleRelease`. Если есть секреты `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` — подписанный release, иначе debug (ставится вручную, этого хватает). Имя файла `TS-<версия>.apk`, чтобы его нашла страница скачивания.
- Настройки облака вшиваются при сборке из тех же секретов/переменных, что у `deploy.yml` (`SUPABASE_PROJECT_REF`, `SUPABASE_ANON_KEY`, `VAPID_PUBLIC_KEY`).
- Push без Firebase: убрать FCM (`@capacitor-firebase/messaging`, `firebase`, `apps/cloud/src/push.ts` FCM-ветку) и сделать уведомления через бесплатный ntfy.sh (своя тема на клиента) или через опрос/Realtime Supabase, когда приложение открыто. Выбери и обоснуй коротко.
- Скрипт для ключа подписи APK: `scripts/android-keystore.mjs` создаёт keystore и печатает, что вставить в какие секреты — **пользователь вставляет сам**.

### 2. ПК кассы: установщик без вопросов
- Проверь результат выпуска `desktop-v0.1.0`; если сборка упала — почини.
- Ключ автообновления: скрипт генерирует пару ключей Tauri, публичный кладёт в `tauri.conf.json`, закрытый — пользователь в секрет `TAURI_SIGNING_PRIVATE_KEY`.
- При первом запуске приложение само находит HUB (`hub.local` / сеть), а если HUB в этом же компьютере не установлен — предлагает «Это главный компьютер клуба? Установить HUB сюда» (вариант для Windows без отдельного мини-ПК).
- В `README` приложения: что делать при окне SmartScreen.

### 3. Мини-ПК: «вставил флешку — работает»
- **Образ для мини-ПК**: GitHub Actions собирает готовый образ Ubuntu Server с предустановленным TS (cloud-init или autoinstall `user-data`), который пишется на флешку через Rufus/balenaEtcher. При первом запуске: мастер на экране мини-ПК или в браузере по адресу `http://<ip>:4310/setup` — ввести `HUB_ID` и `CLOUD_API_KEY` из кабинета (или отсканировать QR, который показывает кабинет управляющего при создании филиала — добавь этот QR), выбрать контроллер ламп, готово.
- Если образ слишком тяжёл для бесплатного CI — вместо него `autoinstall` ISO-ремикс или подробная инструкция «поставить Ubuntu → одна команда». Решение и причины — в README.
- Страница «Скачать приложение» получает раздел **«Мини-ПК клуба»**: ссылка на образ/инструкцию и команду установки.
- Мастер `/setup` — в HUB (`apps/hub`), с тестами; после настройки адрес закрывается.

### 4. Страница «Скачать приложение»
- Крупные кнопки «Скачать для Windows / Android / мини-ПК», определение устройства, версия и дата, QR-код для телефона, короткая инструкция на каждое устройство.
- Если выпуска нет — понятный текст «скоро», без технических слов.
