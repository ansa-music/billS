# Публичный доступ к TS — бесплатно

Как выложить TS в интернет так же, как был выложен прошлый проект (nova-crm): сайты на **Firebase Hosting**, сервер на **Render**, база на **Supabase**. Всё на бесплатных планах.

## Что получится

| Что | Где | Адрес (пример) |
|---|---|---|
| **Кабинет владельца**: все клубы сети, выручка, смены, тарифы. Ставится на телефон как приложение | Firebase Hosting, сайт `ts-app` | `https://ts-app.web.app` |
| **Демо экрана клуба**: зал, касса, бар, оборудование с симулятором ламп. Данные сбрасываются каждую ночь | Firebase Hosting, сайт `ts-app-demo` | `https://ts-app-demo.web.app` |
| **Облако** (API кабинета, приём данных из клубов) | Render, сервис `ts-cloud` | `https://ts-cloud.onrender.com` |
| **Демо-HUB** (сервер демо-клуба) | Render, сервис `ts-demo-hub` | `https://ts-demo-hub.onrender.com` |
| **База облака** | Supabase Postgres | — |

Как это работает:

- Сайты собираются и выкладываются **сами** при каждом пуше в `main`. Это делает GitHub Actions (`.github/workflows/deploy.yml`): тесты, сборка, `firebase deploy`. Для каждого pull request появляется своя временная копия сайта с отдельной ссылкой (preview-канал), ссылку робот пишет прямо в PR.
- Серверы на Render обновляются **сами** по `render.yaml`.
- Кабинет обращается к облаку, а демо-экран к демо-HUB по адресам, которые вшиваются при сборке (`VITE_CLOUD_URL`, `VITE_HUB_URL`). Вход работает по токену в заголовке, без сторонних cookie, поэтому всё работает и на iPhone.

## ⚠️ Сначала про персональные данные

Firebase, Render и Supabase находятся **за пределами Казахстана**. Закон РК «О персональных данных и их защите» требует хранить персональные данные граждан РК на серверах в Казахстане. В облаке TS лежат почта и имена владельцев, имена сотрудников в журнале. Поэтому:

- **Публичное облако из этой инструкции подходит только для демо** и для кабинета без персональных данных: демо-владелец, обезличенные имена.
- **Для пилота с настоящим клубом** персональные данные храните в самом клубе. Это бесплатный режим из `docs/FREE_SETUP_RU.md`: HUB на мини-ПК, облако на мини-ПК клуба, доступ через Tailscale или Cloudflare Tunnel.
- Настоящее облако с реальными данными можно включать только после переезда на хостинг с дата-центром в Казахстане. Код для этого готов: тот же `apps/cloud` и PostgreSQL.

## Что сделать один раз руками

Все аккаунты регистрируете вы: нужен ваш вход и подтверждение. Сам Claude аккаунты не создаёт и пароли не вводит. На всё уйдёт примерно 30–40 минут. Везде удобнее входить **через GitHub** (кнопка «Continue with GitHub»).

### 1. Firebase: сайты

1. Откройте <https://console.firebase.google.com> и войдите аккаунтом Google.
2. **Создать проект** (Add project). Имя: `ts-app`. Если имя занято, Firebase допишет хвост, например `ts-app-1a2b3`. Запомните итоговый **ID проекта**. Google Analytics не нужен. План остаётся **Spark (бесплатный)**, карта не нужна.
3. Слева **Build → Hosting → Get started**. Можно нажимать «Далее» до конца: ставить firebase-tools на компьютер не нужно.
4. Там же, внизу страницы Hosting: **Add another site**. Имя: `<ID проекта>-demo`, например `ts-app-demo`. Это сайт для демо экрана клуба.
5. Если ID проекта не `ts-app`, откройте в репозитории `.firebaserc` и замените `ts-app` в строке `"default"`. Больше ничего менять не нужно: остальное робот подставит сам (`scripts/firebase-targets.mjs`). Если сайт `<проект>-demo` оказался занят и вы назвали его иначе, задайте имя в переменной GitHub `FIREBASE_DEMO_SITE` (см. шаг 4).

### 2. Ключ для робота GitHub

Роботу нужен «сервисный аккаунт», чтобы он мог выкладывать сайты.

1. В консоли Firebase: ⚙️ (рядом с «Project Overview») → **Project settings → Service accounts**.
2. **Generate new private key** → **Generate key**. Скачается JSON-файл. **Никому его не пересылайте и не кладите в репозиторий.**
3. На GitHub откройте репозиторий `ansa-music/billS` → **Settings → Secrets and variables → Actions → New repository secret**.
   - Name: `FIREBASE_SERVICE_ACCOUNT_TS`
   - Secret: всё содержимое JSON-файла целиком.
4. После этого файл с компьютера можно удалить.

Если ругается «нет прав на деплой»: Google Cloud Console → IAM → у этого сервисного аккаунта должны быть роли **Firebase Hosting Admin** и **API Keys Viewer**. Обычно они есть сразу.

### 3. Supabase: база облака

1. <https://supabase.com> → **Start your project** → вход через GitHub.
2. **New project**. Имя `ts`, придумайте **пароль базы** и сохраните его в менеджере паролей. Регион: **Central EU (Frankfurt)**, рядом с Render. План **Free**.
3. Когда проект создастся: кнопка **Connect** вверху → вкладка **Connection string** → **Session pooler**. Нужен именно pooler: Render работает по IPv4, а прямое подключение Supabase идёт только по IPv6.
4. Скопируйте строку вида
   `postgresql://postgres.abcdefgh:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres`
   и вместо `[YOUR-PASSWORD]` подставьте пароль из шага 2. **Не дописывайте** `?sslmode=...`: облако само включает шифрование.

Таблицы создавать не нужно: облако создаёт их само при первом запуске (миграции).

### 4. Render: облако и демо-HUB

1. <https://render.com> → **Get Started** → вход через GitHub. Разрешите доступ к репозиторию `billS`.
2. **New → Blueprint** → выберите репозиторий `ansa-music/billS`, ветка `main`. Render прочитает `render.yaml` и покажет два сервиса: `ts-cloud` и `ts-demo-hub`.
3. Render спросит значение **DATABASE_URL**. Вставьте строку из Supabase (шаг 3.4).
4. **Apply**. Первая сборка займёт 3–5 минут.
5. Откройте каждый сервис и посмотрите его адрес вверху страницы, например `https://ts-cloud.onrender.com`. Если имя было занято, Render допишет хвост: `https://ts-cloud-x1y2.onrender.com`.
6. Если адреса отличаются от `https://ts-cloud.onrender.com` и `https://ts-demo-hub.onrender.com`, сообщите их сайтам. На GitHub: **Settings → Secrets and variables → Actions → вкладка Variables → New repository variable**:
   - `TS_CLOUD_URL` = адрес `ts-cloud`
   - `TS_DEMO_HUB_URL` = адрес `ts-demo-hub`
7. Проверка: откройте `<адрес ts-cloud>/api/health`. Должно прийти `{"ok":true,...}`. Первый раз ответ может идти до минуты.

### 5. Запуск

GitHub → вкладка **Actions** → **Deploy TS to Firebase Hosting** → **Run workflow**. Можно и просто запушить что-нибудь в `main`. Через 3–4 минуты сайты будут доступны:

- кабинет: `https://<проект>.web.app`. Вход демо-владельца: `owner@demo.kz` / `demo1234`;
- демо экрана клуба: `https://<проект>-demo.web.app`. Ключи показаны прямо на странице входа: `OWNER-2222-2222-2222-2222` (владелец), `MGR-3333-3333-3333-3333` (управляющий), `CASH-4444-4444-4444-4444` (кассир), `WTR-5555-5555-5555-5555` (официант).

### 6. (Необязательно) Supabase не должен засыпать

Бесплатный проект Supabase ставится на паузу, если к базе 7 дней никто не обращался. Раз в 3 дня это предотвращает `.github/workflows/keepalive.yml`. Он работает сам, но надёжнее добавить секрет `SUPABASE_DB_URL` с той же строкой подключения, что в шаге 3.4. Тогда он обращается к базе напрямую, даже пока Render спит. GitHub выключает расписание, если в репозитории 60 дней не было коммитов. Тогда включите его заново во вкладке Actions.

## Ограничения бесплатных планов

| Сервис | Ограничение | Что это значит |
|---|---|---|
| **Render Free** | засыпает через 15 минут без запросов; первый запрос после сна ждёт **около минуты** | Демо и кабинет открываются, но первые данные появляются не сразу. Экран клуба пишет «Нет связи с HUB» и сам подключается, когда сервер проснётся |
| Render Free | 750 часов работы в месяц на все сервисы вместе | Два сервиса, которые спят без посетителей, в лимит укладываются. Не держите их разбуженными пингом каждые 10 минут: часов не хватит |
| Render Free | диск стирается при каждом перезапуске и деплое | Облако хранит всё в Supabase, поэтому ничего не теряется. Демо-HUB и так начинает с чистого демо-клуба |
| **Supabase Free** | 500 МБ базы, пауза после 7 дней без активности | На демо места хватит надолго; от паузы защищает keep-alive (шаг 6) |
| **Firebase Spark** | 10 ГБ хранения, 360 МБ трафика в сутки | Хватит с запасом: сайт весит около 1 МБ, повторные заходы берут файлы из кэша телефона |

Демо-клуб сбрасывается каждую ночь в 04:00 по Алматы (`HUB_DEMO_RESET_HOUR`, `HUB_DEMO_TZ` в `render.yaml`). Кроме того, он сбрасывается при каждом засыпании Render, потому что тогда стирается диск. Всё, что посетители натворили (в том числе отозванные демо-ключи), к утру вернётся как было.

## Альтернатива без Render: API на мини-ПК клуба

Если регистрироваться на Render не хочется, облако и HUB можно держать на мини-ПК клуба и открыть их в интернет через **Cloudflare Tunnel** (подробно в `docs/FREE_SETUP_RU.md`). Тогда:

1. на мини-ПК: облако `node apps/cloud/src/main.ts` с `CLOUD_HOST=127.0.0.1`. Туннель даёт адрес вида `https://cloud.<ваш-домен>` или `https://<случайное>.trycloudflare.com`;
2. в переменных GitHub: `TS_CLOUD_URL` = этот адрес (и `TS_DEMO_HUB_URL`, если через туннель открыт и HUB с `HUB_DEMO=1`, `HUB_CORS_ORIGINS=https://*.web.app`);
3. сайты по-прежнему на Firebase. Персональные данные при этом остаются в клубе, в Казахстане.

## Для разработчика

- `firebase.json` описывает два сайта Hosting (multi-site targets `cabinet` и `demo`). Заголовки: `no-cache` для `index.html`, `sw.js`, `manifest.webmanifest`; `immutable` на год для `/assets/**`; SPA rewrite `** → /index.html`. Цели в `.firebaserc` заполняет `node scripts/firebase-targets.mjs` из строки `"default"`.
- `render.yaml` описывает два free web service; health check `/api/health`. У облака есть вариант `/api/health?db=1`, который заодно читает таблицу.
- CORS. Облако по умолчанию пускает `https://*.web.app` и `https://*.firebaseapp.com` (`CLOUD_CORS_ORIGINS`). HUB никого не пускает, пока не задан `HUB_CORS_ORIGINS`. Cookie через домены не ходят. Кабинет на другом домене берёт токен из заголовка `X-Owner-Token` ответа на вход и шлёт его как `Authorization: Bearer`.
- Демо-режим: `npm run demo -w @bills/hub` (`apps/hub/src/demo.ts`). Супервизор запускает HUB с `HUB_DEMO=1` на свежей базе и перезапускает его каждую ночь. HUB выдаёт фиксированные ключи `DEMO_KEYS` (`packages/domain/src/public.ts`) и отвечает на `GET /api/demo`; по этому ответу экран показывает плашку «Демо» и ключи.
- Сборка вручную с адресами:
  `VITE_CLOUD_URL=https://ts-cloud.onrender.com VITE_HUB_URL=https://ts-demo-hub.onrender.com VITE_DEMO=1 npm run build`.
  Без этих переменных фронтенды, как раньше, ходят на свой же домен (`/api`).
