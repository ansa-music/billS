# TS для ПК кассы

Программа для компьютера кассы и мини-ПК в зале. Показывает интерфейс TS с HUB клуба, печатает чеки
сразу на принтер (без окна печати), умеет работать в режиме киоска, запускаться вместе с компьютером
и обновляться сама.

## Установка на Windows

1. Скачайте файл `TS-<версия>-windows-x64-setup.exe` на странице «Скачать приложение» (или в выпусках GitHub).
2. Запустите его, нажмите «Установить» и «Готово» — права администратора не нужны, установка занимает минуту.
   (`.msi` — для системных администраторов, ставит TS для всех пользователей.)
3. **Окно «Windows защитила ваш компьютер» (SmartScreen).** Нажмите **«Подробнее»** →
   **«Выполнить в любом случае»**. Окно появляется потому, что у программы нет платного сертификата
   подписи кода (он стоит денег каждый год). Файл при этом тот же, что собрал GitHub; проверить его
   можно по файлу `.sha256` рядом в выпуске.

Ubuntu/Debian: `sudo apt install ./TS-<версия>-linux-amd64.deb`.

## Первый запуск

TS сам ищет HUB: на этом компьютере, по имени `hub.local` и во всей локальной сети.

- **HUB найден** — TS подключается к нему сам (если их несколько — выберите свой).
- **HUB не найден** — два варианта:
  - **«Это главный компьютер заведения — запустить HUB здесь»** — для заведения без отдельного мини-ПК.
    HUB встроен в TS и запускается за несколько секунд: без интернета, git, npm и пароля
    администратора. Windows может один раз спросить «Разрешить этому приложению вносить изменения?» —
    «Да» открывает доступ планшетам в сети заведения (правило брандмауэра «TS HUB» только для частной и
    доменной сети); если отказаться, HUB всё равно работает на этом компьютере, а доступ можно открыть
    позже: Настройки → «HUB на этом компьютере» → «Открыть доступ планшетам». Затем откроется экран
    «Подключите кассу к кабинету». TS включает автозапуск и при каждом старте запускает HUB сам.
  - **«HUB стоит на другом компьютере — ввести адрес»** — например `192.168.1.10`.

## Встроенный HUB

- Файлы программы: `<папка TS>\hub-bundle\` — официальный `node.exe` (Node.js 24, версия и SHA-256
  закреплены в `scripts/bundle-hub.mjs`), HUB одним файлом `src\main.mjs`, миграции и экран зала `web\`.
- Данные заведения: `%LOCALAPPDATA%\TS\hub\` (Linux: `~/.local/share/TS/hub/`) — `hub.db`, `setup.json`,
  `first-run-keys.txt`, журнал `logs\hub.log` (при 20 МБ — `hub.1.log`). Удаление и обновление TS эту папку
  не трогают. Дополнительные настройки HUB (контроллер ламп, ИБП…) можно положить в `hub.env` там же.
- Команда: `node.exe --env-file-if-exists=<данные>\hub.env <папка TS>\hub-bundle\src\main.mjs` с
  `HUB_DB_PATH=<данные>\hub.db`, `HUB_HOST=0.0.0.0`, `HUB_PORT=4310`, `HUB_WEB_DIST=<папка TS>\hub-bundle\web`.
  Окна консоли нет; HUB перезапускается после падения и после мастера настройки и закрывается вместе с TS.
- Если на порту 4310 уже отвечает HUB (служба, другая копия) — TS просто подключается к нему.
- HUB работает, пока пользователь вошёл в Windows и TS запущен. Чтобы HUB работал до входа в систему,
  есть запасной путь — «HUB как служба» (Настройки → Обслуживание → «Для опытных», скрипты `deploy/windows`).
- Без окна: `TS.exe --hub-only` (только HUB), `TS.exe --open-firewall` (правило брандмауэра).

Сборка установщика на своём компьютере:

```
node scripts/bundle-hub.mjs --node host --check   # apps/desktop/hub-bundle
node apps/desktop/scripts/ci.mjs prepare           # добавляет hub-bundle в ресурсы установщика
cd apps/desktop && npx tauri build --config src-tauri/tauri.ci.conf.json
```

Проверка на настоящем Windows — в GitHub Actions (`desktop.yml`, задачи `windows-smoke`, `linux-smoke`,
`windows-service`): тихая установка, запуск HUB так же, как из приложения, `/api/health`,
`/api/setup/status`, перезапуски, закрытие вместе с TS, удаление без потери базы.

Вернуться к настройкам из интерфейса TS: **Ctrl+Shift+S**.

## Обновления

TS проверяет обновления в «Настройки → Обслуживание → Проверить обновления». Новая версия скачивается
с GitHub и ставится сама; данные клуба хранятся в HUB и не страдают. Обновления подписаны: TS ставит
только то, что подписано ключом клуба.

## Ключ автообновления (один раз)

Нужен, чтобы программы в клубах обновлялись сами. Сделайте это **до первого выпуска**: версии,
собранные без ключа, сами не обновятся — их придётся один раз переустановить вручную.

1. В папке репозитория выполните: `npm run desktop:signing-key`.
   Ключи появятся в папке `.ts-keys\desktop` в вашей папке пользователя (не в репозитории).
   Сохраните копию этой папки (флешка, менеджер паролей): без неё новые версии не подписать.
2. На GitHub: репозиторий → **Settings → Secrets and variables → Actions**:
   - вкладка **Secrets** → «New repository secret»: `TAURI_SIGNING_PRIVATE_KEY` = содержимое `updater.key`
     (скопировать: `npm run desktop:signing-key -- --copy key`);
   - ещё один секрет: `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` = содержимое `password.txt`
     (`npm run desktop:signing-key -- --copy password`);
   - вкладка **Variables** → «New repository variable»: `TAURI_UPDATER_PUBKEY` = содержимое
     `updater.key.pub` (`npm run desktop:signing-key -- --copy pub`). Это открытый ключ, он не секрет.

Код менять не нужно. Сборка сама проверит, что ключи из одной пары; если нет — остановится с
сообщением «ключ подписи обновлений не подходит к открытому ключу».

## Как выпустить новую версию

```
git tag desktop-v0.1.1
git push origin desktop-v0.1.1
```

(или `node scripts/release.mjs desktop`). Версия берётся из метки — править `tauri.conf.json` и
`Cargo.toml` не нужно. GitHub соберёт `setup.exe`, `.msi` и `.deb`, проверит установку на Windows и
Ubuntu и создаст один выпуск «TS для ПК 0.1.1».
Файл для автообновления (`latest.json`) кладётся ещё и в служебный выпуск `desktop-latest` — его
читают установленные программы; удалять его нельзя.

Пробная сборка без выпуска: GitHub → Actions → desktop → «Run workflow» (установщики — в артефактах).
