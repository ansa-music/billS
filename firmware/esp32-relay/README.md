# esp32-relay — контроллер ламп над бильярдными столами

Прошивка для ESP32, которая включает и выключает лампы над столами по команде локального HUB (TS) и сообщает ему, течёт ли ток через каждую лампу. Один контроллер — до 8 столов. Нужно больше — ставится второй контроллер с другим IP.

HUB опрашивает контроллер по HTTP (JSON) в локальной сети. Как HUB устроен в целом — в корневом [README](../../README.md); как монтировать оборудование в клубе — в `docs/INSTALL_HARDWARE_RU.md`.

## Правила поведения

Эти правила вшиты в прошивку — не ломай их при доработках.

1. **Контроллер никогда не выключает реле сам.** Ни по потере связи с HUB, ни по потере сети, ни по таймауту, ни по сторожевому таймеру. Пока на столе идёт игра, свет горит, даже если HUB перезагружается или оборвался Wi-Fi. Единственный способ сменить состояние реле — HTTP-команда.
2. **Состояние реле хранится во флеш-памяти (NVS) и восстанавливается после подачи питания.** Пропало электричество и вернулось — лампы над столами, где шла игра, загораются снова через доли секунды, ещё до подключения к сети. HUB затем сверяет своё состояние с контроллером.
3. **Повтор команды безопасен (идемпотентность).** Два раза «включить реле 3» — всё равно одно включение, одна запись в NVS.
4. **Мигание не меняет сохранённое состояние.** После мигания реле возвращается туда, где было. Любая команда `POST /relay/<ch>` прерывает мигание.
5. **Датчик тока только измеряет.** Он никогда не управляет реле; решения («свет горит без игры» → тревога) принимает HUB.
6. **Сторожевой таймер** (по умолчанию 30 с) только перезагружает ESP32 при зависании программы; после перезагрузки реле восстанавливаются из NVS (правило 2). Пропажа сети не считается зависанием.
7. **loop() неблокирующий:** мигание, измерение тока, переподключение к сети — конечные автоматы на `millis()`, без `delay()`.

## Распиновка (по умолчанию)

### Режим Wi-Fi (по умолчанию)

| Канал (стол) | Реле → IN | Датчик тока → OUT | Примечание |
|---|---|---|---|
| 1 | GPIO 13 | GPIO 36 (VP) | |
| 2 | GPIO 14 | GPIO 39 (VN) | |
| 3 | GPIO 16 | GPIO 34 | |
| 4 | GPIO 17 | GPIO 35 | |
| 5 | GPIO 18 | GPIO 32 | |
| 6 | GPIO 19 | GPIO 33 | |
| 7 | GPIO 21 | — (нет, `-1`) | при Wi-Fi доступны только 6 входов ADC1 |
| 8 | GPIO 22 | — (нет, `-1`) | |

| Прочее | GPIO | Примечание |
|---|---|---|
| Светодиод статуса сети | GPIO 2 | встроенный светодиод DevKit; `-1` — отключить |
| Питание ESP32 | VIN (5V) / GND | от блока питания 5 В |
| Питание модуля реле | VCC → 3V3 ESP32, JD-VCC → +5 В БП, GND общий | снять перемычку VCC–JD-VCC, см. ниже |
| Питание датчиков | VCC → +5 В, GND общий | |

Почему именно эти пины: не strapping-пины (0, 2, 5, 12, 15 — их уровень при загрузке влияет на запуск), не пины флеш-памяти (6–11), не input-only (34–39 — годятся только для датчиков). Пины 34, 35, 36, 39 не имеют подтяжек — для АЦП это как раз хорошо.

### Режим Ethernet (`#define USE_ETHERNET`)

Модуль W5500 занимает шину VSPI: **SCK 18, MISO 19, MOSI 23, CS 5, INT 4** (RST — на 3V3 модуля или свободный GPIO, по умолчанию не подключён). Поэтому реле 5 и 6 переезжают на GPIO 32/33, а освободившиеся входы АЦП — на ADC2, который при Ethernet работает (Wi-Fi выключен):

| Канал | Реле → IN | Датчик → OUT |
|---|---|---|
| 1 | GPIO 13 | GPIO 36 |
| 2 | GPIO 14 | GPIO 39 |
| 3 | GPIO 16 | GPIO 34 |
| 4 | GPIO 17 | GPIO 35 |
| 5 | GPIO 21 | GPIO 25 |
| 6 | GPIO 22 | GPIO 26 |
| 7 | GPIO 32 | GPIO 27 |
| 8 | GPIO 33 | GPIO 15 |

GPIO 15 — strapping-пин, но его уровень при загрузке влияет только на вывод отладочных сообщений в UART, а как аналоговый вход с 2,5 В от датчика он безопасен. Если не хочется его использовать — поставь `-1`, канал 8 будет без датчика.

## Схема подключения одного канала

```
   Фаза L (от автомата) ───────────┐
                                   │
                            ┌──────┴──────┐
                            │  РЕЛЕ k     │  COM ─── NO   (нормально разомкнутый контакт!)
                            │  IN k ◄─────┼──── GPIO реле k (ESP32)
                            └──────┬──────┘
                                   │  NO
                                   │
                          ┌────────┴────────┐
                          │  ДАТЧИК ТОКА k  │  IP+ ─── IP−   (силовые клеммы ACS712
                          │  OUT ──────────►┼──── GPIO АЦП k      или провод в окне SCT-013)
                          │  VCC ─ +5 В     │
                          │  GND ─ общий    │
                          └────────┬────────┘
                                   │
                                   ▼
                            ┌─────────────┐
                            │  ЛАМПА над  │
                            │  столом k   │
                            └──────┬──────┘
                                   │
   Ноль N ─────────────────────────┘

   Настенный выключатель лампы УБИРАЕТСЯ: лампа питается ТОЛЬКО через реле.
   Датчик стоит на том же проводе, что и реле → HUB видит, горит ли свет на самом деле.
```

Общая часть:

```
   Сеть 220 В ──► Автомат ──► Блок питания 5 В/3 А ──┬──► ESP32  VIN (5V), GND
                                                      ├──► Модуль реле  JD-VCC, GND
                                                      └──► Датчики тока  VCC, GND

   ESP32  3V3 ──► Модуль реле VCC   (питание входной стороны оптронов)
   ESP32  GPIO 13,14,16,17,18,19,21,22 ──► IN1..IN8
   ESP32  GPIO 36,39,34,35,32,33     ◄── OUT датчиков 1..6
```

**Модуль реле и уровни 3,3 В.** На модулях с оптронами снимите перемычку `VCC–JD-VCC`: `VCC` подключите к 3V3 ESP32 (тогда входы IN надёжно «видят» высокий уровень 3,3 В и реле не подрагивают), а `JD-VCC` — к +5 В блока питания (катушки реле). Земли общие. При старте ESP32 входы кратковременно в неопределённом состоянии (~100 мс) — для механических реле это незаметно.

**Все реле через контакт NO** (нормально разомкнутый): без питания контроллера свет выключен, включить лампу «мимо системы» нельзя.

## Датчики тока

Прошивка измеряет **среднеквадратичный (RMS) переменный ток** по окну 100 мс (5 периодов сети 50 Гц). Постоянное смещение датчика (2,5 В у ACS712, 1,65 В у модулей SCT-013) вычитается автоматически как среднее по окну, поэтому точная калибровка нуля не нужна. При включении, пока реле канала выключено, дополнительно измеряется собственный шум канала и затем вычитается (`CURRENT_AUTO_ZERO`); результат запоминается в NVS и используется, если при следующем включении реле уже горит.

| Датчик | `CURRENT_SENSOR_MV_PER_A` | Когда брать |
|---|---|---|
| ACS712-05B (±5 А) | 185 | **по умолчанию**: лампы до ~3 А (660 Вт), лучшая чувствительность — видит светодиодные светильники 20–30 Вт |
| ACS712-20A | 100 | лампы до ~8 А; хуже видит слабые LED-светильники |
| ACS712-30A | 66 | не рекомендуется для ламп |
| SCT-013-030 + модуль (1 В / 30 А, со смещением) | 33 | бесконтактный, провод не разрывается; слабая чувствительность — пропустите провод через окно 2–3 раза и умножьте значение (66, 99) |

Выход ACS712 — 2,5 В ± 0,185 В/А при питании 5 В. ESP32 измеряет до ~3,1 В, поэтому при токе более 3 А (5A-версия) сигнал обрежется — для таких ламп берите 20A-версию или добавьте делитель 1:2 на выходе (тогда чувствительность укажите вдвое меньше).

Порог «ток есть» — `CURRENT_ON_THRESHOLD_MA` (по умолчанию 150 мА, с гистерезисом до 100 мА). Ориентиры: лампа накаливания 100 Вт ≈ 450 мА, галогенная 300 Вт ≈ 1,4 А, светодиодный светильник 30 Вт ≈ 150–250 мА (из-за импульсного драйвера больше, чем P/U). После монтажа посмотрите `currentMa` в `/status` при включённой и выключенной лампе и поставьте порог посередине.

**8 датчиков при Wi-Fi.** У ESP32 при работающем Wi-Fi доступен только ADC1 — 6 входов (32, 33, 34, 35, 36, 39). Варианты:
- перейти на Ethernet (W5500) — тогда работают ещё и входы ADC2, все 8 каналов с датчиками;
- оставить каналы 7–8 без датчиков (`-1`) — HUB не получит подтверждения тока по этим столам, но управлять лампами будет;
- поставить два контроллера по 6 столов;
- внешний АЦП (ADS1115 по I²C) — в прошивке не реализован.

## Как прошить (Arduino IDE 2.x)

1. **Установить поддержку ESP32.** *File → Preferences → Additional boards manager URLs*:
   `https://espressif.github.io/arduino-esp32/package_esp32_index.json`
   Затем *Tools → Board → Boards Manager*, найти **esp32 by Espressif Systems**, установить версию **3.x** (3.0.0 и новее).
2. **Установить библиотеку** *Tools → Manage Libraries*: **ArduinoJson** by Benoit Blanchon, версия **7.x**. Остальное (WiFi, ETH, WebServer, Preferences) входит в ядро ESP32.
3. **Открыть скетч**: `firmware/esp32-relay/esp32-relay.ino` (папка должна называться `esp32-relay`, рядом лежит `config.h`).
4. **Настроить `config.h`** (см. следующий раздел).
5. **Выбрать плату и параметры** в меню *Tools*:
   - Board: **ESP32 Dev Module**
   - Upload Speed: 921600 (если не прошивается — 115200)
   - CPU Frequency: 240 MHz
   - Flash Size: 4 MB, Partition Scheme: **Default 4MB with spiffs** (NVS есть в любой схеме)
   - Core Debug Level: None
   - Erase All Flash Before Sketch Upload: **Disabled** (иначе стирается NVS с состоянием реле; при самой первой прошивке можно Enabled)
   - Port: COM-порт платы (драйвер CP210x или CH340 ставится при необходимости)
6. **Upload.** Если плата не входит в режим прошивки — держите кнопку `BOOT` при появлении «Connecting…».
7. Открыть *Serial Monitor* на 115200: контроллер напишет восстановленное состояние реле, шум датчиков, подключение к сети и IP.

Прошивка собирается без предупреждений на Arduino-ESP32 3.x; на ядре 2.x не собирается (другие сигнатуры `esp_task_wdt_init` и `ETH.begin`).

## Настройка сети и `config.h`

Всё в одном файле `config.h`:

| Параметр | Что значит | По умолчанию |
|---|---|---|
| `DEVICE_ID` | имя контроллера (в `/status` и имя хоста) | `esp32-relay` |
| `USE_ETHERNET` | раскомментировать — работать через W5500 вместо Wi-Fi | выкл. |
| `WIFI_SSID`, `WIFI_PASSWORD` | сеть Wi-Fi 2,4 ГГц | — |
| `NET_USE_DHCP` | 0 — статический IP, 1 — DHCP | 0 |
| `NET_IP`, `NET_GATEWAY`, `NET_SUBNET`, `NET_DNS` | адрес **через запятую**: `192, 168, 1, 50` | 192.168.1.50 |
| `API_TOKEN` | токен; пусто — без авторизации | пусто |
| `RELAY_ACTIVE_LOW` | 1 — реле включается низким уровнем (типовые модули), 0 — высоким | 1 |
| `RELAY_PINS[]`, `CURRENT_PINS[]` | пины каналов 1–8; `-1` — датчика нет | см. распиновку |
| `CURRENT_SENSOR_MV_PER_A` | чувствительность датчика | 185 |
| `CURRENT_ON_THRESHOLD_MA` / `CURRENT_OFF_THRESHOLD_MA` | порог «ток есть» / гистерезис | 150 / 100 |
| `CURRENT_AUTO_ZERO` | измерять шум канала при включении | 1 |
| `STATUS_LED_PIN` | светодиод сети | 2 |
| `WDT_TIMEOUT_S` | сторожевой таймер, 0 — выкл. | 30 |

Рекомендации по сети:
- **Статический IP** вне диапазона DHCP роутера (например, DHCP раздаёт .100–.200, контроллеру — .50). HUB обращается к контроллеру именно по IP.
- При DHCP закрепите адрес за MAC контроллера в роутере — иначе после перезагрузки роутера адрес может смениться, и HUB потеряет контроллер.
- **Wi-Fi 2,4 ГГц**, отдельная сеть для оборудования (не гостевая). Если в зале много телефонов и Wi-Fi нестабилен — лучше Ethernet.
- **Токен.** В клубе задайте `API_TOKEN` (случайная строка 16+ символов) и тот же токен укажите в `.env` HUB: `HUB_ESP32_TOKEN=<токен>`. Иначе любой гость в сети Wi-Fi сможет включить свет.

### Как HUB находит контроллер

В HUB включается драйвер `HUB_LAMP_DRIVER=esp32-http` в `.env`, а у каждого стола адрес канала задаётся как

```
esp32:<ip>/<номер реле>        например  esp32:192.168.1.50/3
esp32:<ip>:<порт>/<номер реле> если порт не 80
```

Номер реле — тот, что напечатан на модуле (1–8). Для столов с адресом вида `relay-N` (демо-база) контроллер берётся из `HUB_ESP32_HOST=192.168.1.50`. Подробнее — корневой README, `.env.example` и `docs/INSTALL_HARDWARE_RU.md`.

## Проверка через curl

Подставьте свой IP. Если задан токен — добавьте к каждой команде `-H "Authorization: Bearer <токен>"`.

```bash
# Состояние контроллера и всех каналов
curl -s http://192.168.1.50/status

# Включить реле 1
curl -s -X POST http://192.168.1.50/relay/1 -H "Content-Type: application/json" -d '{"on":true}'

# Выключить реле 1
curl -s -X POST http://192.168.1.50/relay/1 -H "Content-Type: application/json" -d '{"on":false}'

# Мигнуть реле 1 три раза (0,4 с горит / 0,4 с не горит) и вернуть в прежнее состояние
curl -s -X POST http://192.168.1.50/relay/1/blink -H "Content-Type: application/json" -d '{"times":3,"onMs":400,"offMs":400}'

# То же с токеном
curl -s http://192.168.1.50/status -H "Authorization: Bearer MY-SECRET"
```

В Windows PowerShell вместо `curl` используйте `curl.exe` и двойные кавычки внутри экранируйте: `-d "{\"on\":true}"`.

С телефона: откройте `http://192.168.1.50/` — страница с состоянием реле и токами, обновляется каждые 2 секунды (с токеном — `http://192.168.1.50/?token=MY-SECRET`).

Проверка после монтажа, по каждому столу:
1. `POST /relay/N {"on":true}` — лампа над столом N загорелась (если загорелась другая — перепутаны провода реле).
2. `GET /status` через секунду — у канала N `on:true`, `currentOn:true`, `currentMa` правдоподобное (если `currentOn:false` — датчик не на той линии или порог велик).
3. `POST /relay/N {"on":false}` — погасла, `currentOn:false`.
4. Выключите питание контроллера при включённой лампе и включите снова — лампа должна загореться сама до появления сети.

## HTTP API

Порт 80. Все ответы — `Content-Type: application/json`, кроме страницы `/`. Если задан `API_TOKEN`, каждый запрос требует заголовок `Authorization: Bearer <токен>` (или `?token=<токен>`), иначе `401 {"ok":false,"error":"unauthorized"}`.

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/` | — | HTML-страница: id, ip, uptime, таблица реле и токов |
| GET | `/status` | — | `{"ok":true,"id":"esp32-relay","fw":"1.0.0","uptimeMs":12345,"ip":"192.168.1.50","relays":[{"ch":1,"on":true,"currentOn":true,"currentMa":350},{"ch":2,"on":false,"currentOn":null,"currentMa":null},…]}` — 8 элементов; `currentOn`/`currentMa` = `null`, если на канале нет датчика (или первые 100 мс после старта) |
| POST | `/relay/<ch>` (1–8) | `{"on":true}` | `{"ok":true,"ch":3,"state":true,"currentOn":true}` — `state` — фактическое состояние реле после команды; сохраняется в NVS; прерывает мигание. Идемпотентно. |
| POST | `/relay/<ch>/blink` | `{"times":3,"onMs":400,"offMs":400}` — все поля необязательны (по умолчанию 3/400/400; `times` 1–20, интервалы 100–5000 мс, значения вне границ подрезаются) | сразу `{"ok":true,"ch":3,"state":true}` — `state` — состояние, в которое реле вернётся после мигания. Мигание идёт в фоне; NVS не меняется. Повторный `blink` перезапускает мигание от исходного состояния. |

Ошибки:

| Код | Когда | Тело |
|---|---|---|
| 400 | тело не JSON, нет поля `on`, `times`/`onMs`/`offMs` не целые | `{"ok":false,"error":"…"}` |
| 401 | нет или неверный токен | `{"ok":false,"error":"unauthorized"}` |
| 404 | канал вне 1–8 или неизвестный путь | `{"ok":false,"error":"unknown channel"}` / `"not found"` |
| 405 | GET на `/relay/…` | `{"ok":false,"error":"method not allowed"}` |

Показание тока обновляется раз в 100 мс, поэтому `currentOn` в ответе на `POST /relay` отражает ток **до** переключения; реальное состояние линии HUB увидит в следующем `GET /status` (через 100–200 мс). Любой запрос обрабатывается за миллисекунды, очередь на контроллере не копится.

## Поведение при отказах

| Что случилось | Что делает контроллер | Что делает HUB |
|---|---|---|
| Пропало питание контроллера | реле обесточены → лампы гаснут (ставьте контроллер и HUB на ИБП). При возврате питания реле восстанавливаются из NVS ещё до подключения к сети: лампы столов с играми загораются снова | по правилу «время считается от реального начала игры» — гости не платят за простой; при появлении контроллера сверяет состояние |
| Пропала сеть Wi-Fi / Ethernet | **реле не трогает**, светодиод мигает, переподключается каждые 15 с (Wi-Fi) или по появлению линка (Ethernet) | команды копятся в очереди и повторяются; столы не открываются, пока лампа не подтвердит включение |
| HUB выключен / перезагружается | **реле не трогает** — ничего не замечает, просто нет запросов. Таймаутов «погасить, если HUB молчит» нет и быть не должно | после старта досылает незавершённые команды и выравнивает лампы |
| Зависла программа контроллера | сторожевой таймер (30 с) перезагружает ESP32; реле восстанавливаются из NVS; сеть и HTTP поднимаются заново | кратковременная недоступность, повтор команд |
| Сгорело реле / не горит лампа при `on:true` | `currentOn:false` при `on:true` | тревога «игра идёт, а свет не горит» |
| Лампу подключили мимо реле | `currentOn:true` при `on:false` | тревога «свет горит без игры» (защита от включения «своим») |
| Датчика на канале нет (`-1`) | `currentOn:null` | управляет лампой без подтверждения тока |
| Повтор команды (двойное нажатие, обрыв ответа) | идемпотентно: то же состояние, NVS не перезаписывается | использует `Idempotency-Key`, см. корневой README |

Ресурс NVS — порядка 100 000 перезаписей на ключ; запись происходит только при реальном изменении состояния (несколько раз в день на стол), так что хватит на десятки лет.
